# Этапы разработки

Статус: предварительная последовательность, без оценки сроков до уточнения объёма.

## Этап 0. Согласовать первую версию

- Уточнить необходимость работы без интернета, общей кампании на устройствах и редакцию D&D. Компьютер и телефон уже подтверждены.
- Уточнить сценарии подтверждённых приоритетов: бой, подготовка сюжета и сохранение событий.
- Разобрать пример подготовки, проведения и завершения одной сессии.
- Утвердить границы первой версии и выбрать стек.
- Подготовить GitHub-репозиторий с документацией.

Готово, когда решения записаны, репозиторий доступен и понятно, какую сессию используем для проверки.

## Этап 1. Кампания и база знаний

- Создание и редактирование кампании.
- Создание, редактирование и удаление записей.
- Теги, связи и обратные ссылки.
- Поиск внутри кампании.
- Постоянное хранение данных.

Готово, когда можно создать NPC и место, связать их, переименовать запись без потери связи, найти её по тексту и открыть данные после перезапуска. Записи другой кампании не попадают в результаты.

## Этап 2. Полный цикл сессии

- Подготовка сессии из упорядоченных сцен.
- Привязка записей базы знаний к сценам.
- Экран проведения и быстрые заметки.
- Простой трекер боя: участники, инициатива, здоровье, ход, раунд и сохранение состояния.
- Завершение сессии и отчёт с последствиями.
- Проверка основных действий на компьютере и телефоне.
- Экспорт кампании и восстановление из него.

Готово, когда мастер проводит пробную сессию, сохраняет итоги и восстанавливает кампанию со всеми связями в чистое хранилище. Повреждённый импорт отклоняется без потери существующих данных. Бой продолжается с того же хода после перезапуска; проверены равная инициатива, смена раунда, удаление активного участника и исправление ошибочного действия. План сессии и бой доступны на телефоне без обязательного горизонтального скролла.

## Этап 3. Проверка на игре

- Провести настоящую сессию.
- Собрать затруднения и наблюдения.
- Исправить потери данных, неудобный поиск и действия, мешающие темпу игры.
- Выбрать следующий приоритет: развитие боя, подготовка контента или справочник.

Готово, когда основные сценарии работают на материалах реальной кампании и определены наиболее полезные следующие задачи.

## Этап 4. Расширение

Добавлять по результатам игры: инструменты боя, справочник, генераторы, помощь ИИ, синхронизацию, доступ игроков и другие системы. Для каждой возможности сначала описать пользовательский сценарий и критерий готовности.

## Первые задачи для GitHub

Создать issues после уточнения первой версии; пока это заготовки:

| Задача | Зависит от | Критерий готовности |
| --- | --- | --- |
| Выбрать платформу и стек | Ответы владельца | Решение с причинами записано |
| Создать каркас приложения | Выбор стека | Приложение запускается по инструкции |
| Реализовать кампании и хранение | Каркас | Кампания сохраняется после перезапуска |
| Реализовать записи и связи | Кампании | CRUD и переименование сохраняют целостность |
| Добавить поиск | Записи | Поиск по заголовку и тексту ограничен кампанией |
| Добавить план и проведение сессии | Записи | План, материалы и журнал доступны в одном сценарии |
| Добавить простой трекер боя | Проведение | Сохраняются участники, здоровье, порядок ходов и раунд; бой можно продолжить |
| Проверить интерфейс на телефоне и компьютере | Основные экраны | План, записи и бой доступны на обоих устройствах |
| Добавить итоги сессии | Проведение | Отчёт сохранён и связан с материалами |
| Добавить экспорт и импорт | Модель данных | Кампания восстанавливается без потери связей |
| Провести пилот | Полный цикл и восстановление | Записаны результаты настоящей игры |
