# База знаний и память помощника — 0.5

## Работа с заметками

Слева — дерево папок, поиск и сворачиваемые фильтры. В центре — открытая заметка и до шести последних вкладок. Справа — свойства, ближайшие связи, исходящие и обратные ссылки. На узком окне правая панель скрывается; свойства остаются доступны отдельной кнопкой.

«Писать» включает редактор Markdown. `Ctrl/⌘ + S` записывает заметку в кампанию. «Читать» показывает предварительный результат, включая ещё не сохранённый текст: статус внизу сообщает о черновике. Черновики разделены по кампании и записи и сохраняются в sessionStorage этой вкладки; переходы между экранами и перезагрузка не стирают их. Полное закрытие окна может удалить sessionStorage, поэтому перед закрытием нужно сохранить заметку. Ошибка записи оставляет текст доступным для копирования и повторной попытки.

Папка задаётся в «Свойствах», например `Мир/Побережье`. Отдельных пустых папок пока нет. Там же меняются название, теги, тип, характеристики и явные связи. При переносе или переименовании автоматически обновляются однозначно разрешённые ссылки из других заметок.

Поддерживаемая разметка:

```md
# Заголовок
## Сцена
**Важно** и *подробность*
- Первый пункт
- Второй пункт
> Цитата
[[Мира Вейл]]
[[Мир/Побережье/Старый маяк|маяк]]
```

Также доступны нумерованные списки, горизонтальные разделители, встроенный и ограждённый тройными обратными кавычками код, обычные HTTP(S)-ссылки. Это ограниченный рендерер, не полная реализация CommonMark: таблиц, вложенных списков, изображений и расширений Obsidian пока нет. Якорь `#Заголовок` разрешает целевую заметку, но не прокручивает к разделу. HTML отображается текстом. Ссылки внутри кода не создают связей. Отсутствующая или неоднозначная ссылка помечена пунктиром; при совпадении названий нужен путь с папкой. По нажатию отсутствующей ссылки открывается форма создания записи.

«↓ .md» скачивает сохранённую версию текущей заметки с YAML-свойствами. В Electron заметки также записываются в `campaigns/<ID>/notes/` выбранного хранилища. Открой эту папку в Obsidian; внешние правки, новые файлы, перемещения и удаления считываются при входе в базу знаний или через «Хранилище → Обновить записи». Поле `dmw-id` связывает файл с карточкой, его нельзя дублировать. Тип, теги и характеристики редактируются в приложении и остаются в SQLite. Файловые вложения Obsidian, плагины и произвольные YAML-свойства не импортируются. В прежней веб-версии основная база остаётся в IndexedDB.

## Настоящие файлы памяти

Открой «ИИ-помощник → Markdown-память». Кнопка «+ Запись» создаёт файл в выбранной области. Путь к папке показан в «Открыть в Obsidian и сохранить копию». Настольное приложение создаёт её при первом открытии памяти. Все пути ниже относительно выбранного хранилища; в веб-версии память находится в `vault/memory/` проекта.

```text
memory/
  shared/
    Мой стиль.md
  campaigns/
    <ID кампании>/
      Важные факты.md
      journal/
        <дата>-<ID ответа>.md
```

В Obsidian выбери «Открыть папку как хранилище» и укажи `memory/`. Можно редактировать существующие файлы и создавать новые `.md` в `shared/` или папке нужной кампании, включая вложенные папки. Файлы вне этих областей помощник не читает. `shared/` предназначена для стиля, без секретов и событий отдельных миров. Скрытые папки, включая `.obsidian`, не индексируются. Символические ссылки в читаемых путях запрещены.

Перед каждым запросом файлы перечитываются с диска. Пока используется поиск по словам, а не векторный поиск: в контекст попадает до четырёх файлов (до двух общих и двух кампании), суммарно не более 3200 символов. Выбираются подходящие и свежие записи. Полная память не помещается в каждый запрос; лучше держать файлы короткими и писать имена нужных персонажей в вопросе. Общий профиль и одобренные примеры тоже остаются частью контекста.

Каждый новый завершённый разговор автоматически сохраняется в `journal/`. Это накопление эпизодической памяти. Тексты явно помечаются как разговоры и предложения, а не подтверждённые события мира. Канон продолжает задавать мастер. Модель не получает права выполнять команды и произвольно переписывать файлы. Для исправления воспоминания открой файл в приложении или Obsidian; обновлённая версия будет прочитана в следующем запросе.

Если файл изменился после открытия редактора приложения, сохранение отклоняется. Скопируй свой текст, закрой редактор, обнови список и сравни версии. Чужая правка не будет молча затёрта. Удаление записи памяти удаляет реальный файл после подтверждения. Очистка переписки в браузере не удаляет Markdown-журналы; для удаления памяти разговоров их нужно удалить отдельно.

Ограничения: UTF-8, до 80 КБ на файл, до 512 файлов и 20 МБ на каждую область (общую или одну кампанию), до пяти частей пути. При достижении лимита перенеси старые журналы за пределы читаемых папок. Ошибка записи журнала показывается отдельно: ответ уже сохранён в переписке. Кнопка повтора доступна до закрытия вкладки; после закрытия исходный разговор можно восстановить из сохранённой переписки вручную. Старые разговоры автоматически в файлы не переносятся.

В настольной версии файловый API запускается вместе с окном; интернет не нужен. В веб-версии для файлового API нужен работающий локальный сервер приложения. При остановленном сервере файлы можно читать в Obsidian, а в PWA доступны база знаний, браузерная память стиля и переписка. Импорт JSON создаёт новый ID кампании. В Electron затем используй «Хранилище → Импорт папки памяти», чтобы сопоставить файлы со старым ID. Полная настольная копия переносит память и переназначает ID автоматически.

## Память и дообучение

Локальность не запрещает обучение. LoRA обучает небольшие дополнительные матрицы, меняющие поведение модели, при замороженных базовых весах. Для этого нужны отобранные примеры, совместимый обучающий инструмент и достаточная память оборудования. Ollama умеет импортировать поддерживаемые обученные модели/адаптеры; сам процесс обучения — отдельный шаг. Поддержку конкретного адаптера для установленной Qwen3.5 ещё нужно проверить. [PEFT: LoRA](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora), [Ollama: импорт](https://docs.ollama.com/import).

Markdown-память решает другую задачу: хранит изменяемые сведения между запусками и подаёт подходящие записи в запрос. Чтобы помнить новый факт, не нужно заново обучать веса. Сейчас реализован этот механизм; автоматического обучения после диалогов нет. Память делает сведения доступными модели, но не гарантирует их точное применение: в проверке Qwen3.5 4B иногда игнорировал требование к началу ответа, присутствующее в контексте. Для будущего дообучения полезны пары «запрос → исправленный/одобренный ответ» с отделением стиля от фактов конкретной кампании и отдельной проверкой качества.

## Резервная копия и источники интерфейса

В Electron «Хранилище → Сохранить полную копию» включает все кампании, заметки, аудио, профиль и файлы памяти. Восстановление создаёт новое независимое хранилище. Одиночный JSON кампании включает её заметки, аудио и последние 100 сообщений; профиль и файловая память в этот JSON не входят. В веб-версии профиль нужно экспортировать отдельно и скопировать всю `vault/`. Личные данные исключены из публичного Git.

В интерфейсе использованы подходы документов мира и видимых связей из [VVD](https://vvd.world/compare/obsidian), локальных редактируемых файлов из [Obsidian](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data), а также [wiki-ссылок](https://help.obsidian.md/Linking+notes+and+files/Internal+links) и [обратных ссылок](https://help.obsidian.md/Plugins/Backlinks). Исследованы публичные страницы и официальная документация; закрытый интерфейс VVD не тестировался. Копирование графики и кода этих продуктов не использовалось.
