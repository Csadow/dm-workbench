# Как использовать Arch Linux / Hyprland для DM Workbench

Проверено 2026-09-27 по локальным настройкам и работающим службам. Это план интеграции; в 0.6 реализованы общая тёмная тема и следование системной теме. Правила окон, назначенные клавиши и настройки сна пользователя не изменялись.

## Что есть в текущем окружении

| Компонент | Наблюдение | Польза для приложения |
| --- | --- | --- |
| Hyprland 0.56.2 | Lua-конфиги, собственные дополнения в `~/.config/hypr/custom/` | Рабочее пространство игры, правила размещения, вызов окна с клавиатуры |
| Quickshell | Запущен `qs -c ii`; установленная Caelestia не означает, что она активна | Имеющиеся поиск приложений, обзор рабочих пространств, панель медиа и уведомления |
| Оформление | `prefer-dark`, `adw-gtk3-dark`; текущая схема содержит почти чёрные поверхности и розовый акцент | Общая тёмная тема приложения, без яркой вспышки при старте |
| Экран | Один активный монитор 1920×1080, масштаб 1, около 165 Гц | Основное окно на отдельном рабочем пространстве; дополнительные панели по запросу |
| PipeWire + WirePlumber | Обе службы активны; в автозапуске предусмотрен EasyEffects | Отдельная громкость и направление звука приложения |
| `playerctl` | Установлен; медиаклавиши вызывают play/pause/next/previous | Основа управления музыкой без перехода из заметок или другого приложения |
| Буфер обмена | Работают `wl-paste` и `cliphist`; доступ через `Super+V` | Быстрая вставка фрагментов правил и заметок |
| hypridle | Процесс работает; блокировка через 300 с, выключение экрана через 600 с, сон через 900 с | Нужен явный режим проведения игры для длинных разговорных сцен |
| Портал | `xdg-desktop-portal-hyprland` активен | Системные механизмы выбора экрана и разрешений при будущей работе с окном игроков |

Источник наблюдений: `hyprctl version/monitors/clients`, запросы GSettings, список процессов/пакетов и соответствующие конфиги. Пользовательские файлы конфигурации не копируются в репозиторий. Значения отражают момент проверки, а не обязательные требования к запуску.

## Приоритеты

### 1. Рабочее пространство ДМа

Основному окну подходят полноценное рабочее пространство и быстрый возврат через обзор `Super+Tab`. На 1080p деление приложения с минимальной шириной 960 px и браузера поровну тесное: полезнее переключать пространства или показывать справочник поверх игры. Для будущего небольшого окна звуков/быстрой заметки подойдёт специальное рабочее пространство, уже знакомое по существующему `Super+S`.

Не стоит назначать приложению `Super+D`: в конфигурации это уже переключение максимизации. `Super+M` занят панелью медиа. Новую клавишу нужно выбирать по фактическому списку `hyprctl binds`, а правило окна — по `class` из `hyprctl clients`, не по предположению, что имя программы равно классу.

Добавления следует держать в `custom/keybinds.lua` и `custom/rules.lua`, чтобы обновления набора конфигов не стирали их. Для установленной ветки актуален Lua; старые примеры с `windowrulev2` переносить буквально не нужно. [Рабочие пространства](https://wiki.hypr.land/Configuring/Basics/Workspace-Rules/), [правила окон](https://wiki.hypr.land/Configuring/Basics/Window-Rules/).

### 2. Управление музыкой через существующую оболочку

В системе уже есть `Super+Shift+P` / медиаклавиша Play для `playerctl play-pause`, `Super+M` для панели Quickshell и `Ctrl+Super+V` для микшера. В следующей итерации имеет смысл связать музыку приложения с Media Session / MPRIS: показывать название сцены, ставить на паузу и возобновлять все музыкальные/атмосферные слои вместе. Короткие эффекты не должны становиться отдельной «песней» и вытеснять основной трек.

Это ещё не реализовано и требует проверки в Electron: обычное воспроизведение HTML Audio не гарантирует правильную семантику нескольких слоёв. Нужны сохранение позиции при паузе, явная остановка и предсказуемый выбор проигрывателя при одновременно открытом браузере. Quickshell уже умеет работать с MPRIS-проигрывателями. [API Quickshell](https://quickshell.org/docs/v0.2.1/types/Quickshell.Services.Mpris/MprisPlayer/).

PipeWire позволит направить звук приложения на колонки стола или в отдельный виртуальный выход для голосовой связи. Сначала достаточно ручной маршрутизации в микшере; затем можно добавить выбор устройства в приложении. Не следует обещать три независимых системных выхода «музыка / атмосфера / эффекты»: сейчас это категории внутреннего микшера, отдельные выходы ещё нужно реализовать. [Маршрутизация PipeWire](https://docs.pipewire.org/page_man_pw-link_1.html).

### 3. Явный режим проведения игры

Во время разговора с игроками мастер может долго не трогать клавиатуру. При текущих настройках это способно привести к блокировке, гашению экрана или сну. Полезна отдельная кнопка «Идёт игра», которая временно запрашивает запрет простоя, показывает активный статус и снимает его после завершения игры/закрытия окна.

Нельзя считать обычный запрет сна полной заменой idle-inhibitor: нужно проверить блокировку, DPMS и suspend отдельно именно с hypridle. Также режим не должен отменять ручную блокировку. В Electron есть `powerSaveBlocker`; hypridle учитывает несколько видов inhibitors, если соответствующие исключения не включены. Постоянно отключать hypridle для решения этой задачи не требуется. [Electron](https://www.electronjs.org/docs/latest/api/power-save-blocker), [hypridle](https://wiki.hypr.land/Hypr-Ecosystem/hypridle/).

### 4. Сбор материалов и Markdown

`Super+V` уже ускоряет перенос текстов в базу знаний. В конфигурации есть `Super+Shift+X` для OCR и установлен Tesseract. Полезное развитие — действие «Новая заметка из вставленного текста», выбор типа и явное поле источника. Распознанные характеристики монстров нужно проверять; OCR не гарантирует точности чисел.

Фоновое чтение всей истории буфера и автоматическая отправка выделения помощнику не нужны: достаточно обычной явной вставки. Markdown-файлы уже доступны редакторам на компьютере. Дальнейшее улучшение — наблюдение за папкой с аккуратным согласованием конфликтов вместо необходимости вручную обновлять записи.

Включены раскладки `us,ru`. Текущие сочетания приложения по `event.key` стоит отдельно доработать для русской раскладки: `Ctrl+S` и `Ctrl+K` должны работать по физической клавише с учётом IME, даже когда вводятся «ы» и «л». Это отдельная небольшая задача, не изменение глобальных клавиш Hyprland.

### 5. Установка и обновление в Arch

Переносимая Electron-сборка работает без Node.js у пользователя. Дальше полезен `PKGBUILD` для локального пакета: стабильный путь запуска, `.desktop` и иконка устанавливаются вместе, данные остаются в выбранном хранилище. AUR-публикация и автоматическое обновление пока не сделаны.

Следует сохранить собственную проверенную версию Electron. Использование произвольного системного Electron в rolling-release окружении означает дополнительную матрицу совместимости. Начиная с Electron 38, Wayland выбирается автоматически в соответствующей сессии; устаревшие наборы флагов не стоит добавлять без необходимости. Фактический режим нужно проверять полем `xwayland` в `hyprctl clients`. [Изменения Electron](https://www.electronjs.org/docs/latest/breaking-changes/#breaking-api-changes-380).

## Что сделано в 0.6

Общая палитра применяется к кампаниям, базе знаний, бою, бестиарию, музыке, ИИ и формам. Тёмный режим включён по умолчанию. В верхней панели доступны «Тёмная», «Светлая», «Как в системе»; выбор сохраняется между запусками, а смена темы не пересоздаёт редактор и не теряет черновик.

В Electron настройка также передаётся `nativeTheme`, поэтому меню и поддерживаемые системные элементы следуют выбранному режиму. Режим «Как в системе» использует `prefers-color-scheme`. Скрипт Quickshell `switchwall.sh` обновляет GSettings при переключении светлого/тёмного режима; в текущем конфиге это `Ctrl+Super+Shift+D`. Таким образом, системный режим приложения использует уже существующий сигнал оформления. [Electron nativeTheme](https://www.electronjs.org/docs/latest/api/native-theme).

Розовый акцент выбран по текущей палитре рабочего стола, но это стабильная палитра приложения. Автоматическое чтение цветов обоев, запуск Lua-файлов и импорт сгенерированных цветов не добавлены. Если это понадобится, стоит читать ограниченный набор цветов из JSON Matugen и проверять контраст, сохраняя независимость цветов урона и лечения.

Предлагаемый порядок следующей работы: режим игры → медиаклавиши/MPRIS → рабочее пространство и небольшая панель звуков → пакет Arch. Уведомления о готовом ответе ИИ пригодятся позже, при работе в другом окне; текст кампании в системном уведомлении показывать необязательно.
