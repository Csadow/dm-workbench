# Настольная версия 0.6

Проверенная платформа — Linux x64. Electron 44.4.5 включает Chromium и Node.js; отдельный Node для готовой сборки не нужен. Интернет нужен для первоначальной установки/обновления программы и загрузки модели. Обычная работа, бестиарий, музыка и ответы установленной локальной модели доступны без интернета.

## Запуск и данные

Готовая сборка: распаковать архив и запустить `start.sh`. Из исходников: Node.js 24+, `pnpm install --frozen-lockfile --ignore-scripts`, `node node_modules/electron/install.js`, `pnpm start`. Сборка: `pnpm package:linux`. Архив появляется в `dist/`; веса модели, пользовательские данные и зависимости разработки туда не входят.

Начальная папка — `DM Workbench` внутри системной папки документов. «Хранилище → Открыть другое хранилище» выбирает пустую папку или существующую базу приложения. Переключение не перемещает старые данные. Для переноса сделай полную копию и восстанови её в нужном месте. Перед переключением сохрани черновики и заверши запросы ИИ.

```text
DM Workbench/
  workbench.sqlite          # кампании, профиль, индексы и журнал записи
  campaigns/<ID>/
    notes/<Папка>/<Имя>.md  # текст базы знаний
    audio/<ID>.wav          # либо mp3/ogg/другой поддержанный формат
  memory/
    shared/                 # общий стиль
    campaigns/<ID>/         # память и journal разговоров
  backups/                  # последние 14 ежедневных копий
  .trash/                   # файлы, удалённые приложением
```

SQLite может иметь служебные файлы `-wal` и `-shm` во время работы. Не копируй один SQLite-файл как полную резервную копию открытого приложения; используй встроенный экспорт. Конфигурация окна/путей и движок ИИ находятся отдельно, в пользовательском профиле Electron. Переменные для разработки: `DMW_DATA_DIR`, `DMW_USER_DATA_DIR`, `DMW_AI_DIR`.

## Оформление

Тема выбирается в верхней панели: тёмная (по умолчанию), светлая или системная. Она применяется до первого отображения страницы, включая цвет фона окна Electron. Смена темы не пересоздаёт формы, не очищает текст и выделение.

В Electron выбор хранится в `desktop.json` пользовательского профиля и локальном кеше интерфейса; в веб-версии — в localStorage. Это настройка приложения, не кампании: в полную копию кампаний она не входит. Системный режим следует `prefers-color-scheme`, а встроенные элементы Electron используют `nativeTheme`.

[Анализ Hyprland / Arch](research/hyprland-arch.md) описывает проверенные особенности окружения и приоритеты следующих интеграций.

## Obsidian и согласование правок

Открой `campaigns/<ID>/notes/` как хранилище Obsidian. Обычные UTF-8 `.md` можно редактировать, создавать, перемещать и удалять. Считывание происходит при входе в базу знаний, по кнопке «Обновить записи», перед сохранением кампании и экспортом. Непрерывного наблюдения за папкой пока нет.

Начало файла содержит `dmw-id`: сохраняй его при переименовании, не копируй в новую заметку. Для нового документа достаточно обычного Markdown без ID — приложение присвоит его само. Внешние имя и папка берутся из пути, текст — из файла. Тип, теги, характеристики существ, явные ID-связи, сессии и бой остаются в SQLite. Переименование однозначно найденной записи обновляет wiki-ссылки; удаление убирает ID-связи. Неоднозначные текстовые ссылки требуют уточнения пути.

Скрытые папки не читаются; симлинки запрещены. Индексация ограничена 12 000 файлами / 25 МБ на кампанию и 500 КБ на заметку, но общий сохраняемый документ кампании по-прежнему ограничен 5 МБ. Плагины, вложения, произвольные свойства YAML и полный синтаксис Obsidian не реализованы. Удаление `.md` означает удаление записи из кампании, поэтому перед массовыми изменениями создай копию.

Устаревший редактор получает ошибку вместо перезаписи внешнего изменения. Скопируй черновик, обнови записи и сравни версии. Состояние SQLite и ожидаемые изменения Markdown/audio фиксируются одной транзакцией, затем файлы заменяются через временный файл и rename. При прерывании журнал завершается на следующем запуске. Если файл изменён уже после фиксации операции, приложение останавливает её и показывает путь; исходные данные не затираются. Реальное отключение питания и исчерпание диска не тестировались; автоматическая проверка имитирует отказ записи после транзакции.

## Резервные копии и импорт

«Сохранить полную копию» создаёт сжатый `.dmw-backup.json.gz`: все кампании, Markdown-тексты заметок, аудио, профиль и файловая память. «Восстановить копию» проверяет содержимое и создаёт новую папку с независимыми ID, сохраняя соответствие памяти кампаниям. Лимит распакованной полной копии — 500 МБ. Модель, `.obsidian`, `.trash`, настройки окна и внутренняя история версий в копию не входят.

При открытии непустого хранилища создаётся одна автоматическая копия за день, остаются последние 14. Это копия на том же диске: отдельную копию для защиты от поломки устройства нужно сохранять вручную. Текущая реализация не делает копию после каждого сохранения и не создаёт её по таймеру в постоянно открытом окне. SQLite дополнительно хранит последние 20 документов кампании, но интерфейса восстановления этих версий пока нет. Файлы `.trash` автоматически не очищаются и могут занимать место.

Для веб-версии сначала экспортируй JSON каждой кампании, затем профиль стиля. Импортируй их в Electron. После этого «Импорт папки памяти» с выбранной старой `vault/memory/` сопоставит старые ID новым; неизвестные кампании и уже существующие файлы пропускаются. Повторный импорт одной кампании привязывает последующий перенос памяти к последней импортированной копии. Сам браузерный профиль программа не читает и не удаляет.

## Локальный ИИ

Настольная версия запускает Ollama сама. Уже работающий локальный процесс переиспользуется и не завершается при выходе. «Подключить установленный ИИ» выбирает каталог с `runtime/bin/ollama` и `models/`; уже работающий внешний Ollama имеет приоритет. Запуск из исходников использует `.local-ai` проекта, готовая сборка — папку ИИ в своём пользовательском профиле. Загрузку Linux x64 можно запустить кнопкой, нужны `curl`, `tar`, `zstd` и около 4,8 ГБ трафика; распакованные файлы занимают больше места.

Окно работает и при недоступном ИИ. Модель видит ограниченную выборку фактов и редактируемой памяти, её веса не дообучаются. [Подробнее](local-assistant.md).

## Проверки и границы

- `pnpm test`: предметная логика, формат импорта, SQLite, внешние правки, защита ревизий, незавершённая запись, полная копия.
- `pnpm test:desktop`: настоящий Electron, импорт веб-данных через интерфейс, аудио, чтение диска, тестовый локальный ИИ, восстановление и перезапуск.
- `DMW_TEST_BINARY=/полный/путь/dm-workbench node scripts/test-desktop.mjs`: те же сценарии на готовой сборке.
- `pnpm test:browser`: регрессия старой веб-версии, включая запуск с выключенным сервером.

Electron renderer работает с sandbox/contextIsolation, без Node.js. Узкий preload-мост проверяется в главном процессе. Внешние ссылки открываются в системном браузере. Для CI допускается `DMW_TEST_NO_SANDBOX=1` только в изолированной тестовой среде; обычный запуск не отключает sandbox. Нет системного установщика, подписи, автоматического обновления и проверенных сборок Windows/macOS.
