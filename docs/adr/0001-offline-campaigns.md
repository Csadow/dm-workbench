# ADR 0001: автономная работа и отдельные кампании

Дата: 2026-09-27.

Статус: PWA и локальное хранение реализованы в прототипе 0.1. Обновление: по уточнению владельца целевая платформа — компьютер. [Реализация и ограничения](../prototype.md).

## Контекст

Компьютер — целевая платформа; требование мобильной версии отменено владельцем. Требуется работа без интернета и сохранение нескольких кампаний. Автоматическую синхронизацию можно исключить. Приоритеты: сюжет, бой и история событий. [Исследование аналогов](../research/tools-comparison.md) поддерживает сочетание локальной базы знаний и специального экрана проведения.

## Решение для прототипа

- Адаптивная PWA без регистрации. Установка и обновления используют сеть; подготовленное приложение работает без сети.
- Локальная IndexedDB для данных; service worker и Cache API для файлов интерфейса. Все обязательные ресурсы поставляются вместе с приложением.
- Каждая кампания имеет стабильный ID, свою базу записей, сессии, журнал и бои. В интерфейсе всегда видно активную кампанию.
- Перенос между устройствами — экспорт и импорт файла. Автоматического слияния изменений нет.
- Первый модуль правил — `dnd-5.5e-2024`, с фиксируемой версией источника `srd-5.2.1`. Последующие обновления не меняют правила существующей кампании молча.
- В прототипе используются ES-модули и встроенный API IndexedDB без внешних библиотек; отдельный backend не требуется.

## Рассмотренные варианты

| Вариант | Соответствие задаче | Вывод |
| --- | --- | --- |
| PWA с локальными данными | Интерфейс для компьютера, автономность после загрузки; нужны экспорт и проверка поведения браузеров | Проверено в Chromium/Linux, далее пилот |
| Устанавливаемое приложение с локальной базой | Подходит автономному сценарию; отдельная упаковка и проверка на каждой целевой ОС | Резервный путь при ограничениях PWA |
| Веб-приложение с сервером и синхронизацией | Добавляет аккаунты, сервер и разрешение конфликтов | Не входит в первую версию |

Основание для веб-варианта: [офлайн-работа PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation), [транзакции IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API). Выбор варианта подтверждён сквозным тестом в Chromium/Linux; другие ОС и реальная игра ещё не проверены.

## Сохранение и резервная копия

Изменения боя сохраняются сразу, текстовые формы — кнопкой «Сохранить»; «Сохранено» показывается после успешной транзакции. Экспорт создаёт отдельный файл, который переживает удаление данных приложения. Локальная история внутри той же базы не заменяет внешнюю копию.

Прототип использует `*.dmw.json`: `formatVersion`, `exportedAt`, метаданные кампании, версия правил, записи, связи, сессии с текстовым планом сцен, журнал, текущий бой, участники и история отмены. Экспорт — согласованный снимок одной кампании; текстовые материалы включены полностью, сетевые ссылки не считаются сохранённым содержимым. Вложения пока вне объёма.

Импорт сначала проверяет версию формата, типы полей, уникальность ID и все ссылки. Первая версия импортирует **как новую кампанию**, переназначая ID и внутренние ссылки. Существующие кампании не перезаписываются. Повторный импорт явно создаёт отдельную копию; автоматического объединения нет. Запись выполняется атомарно, ошибка оставляет прежнее хранилище целым.

Перенос: экспортировать на компьютере → передать файл любым доступным способом → импортировать на другом компьютере. Копии дальше независимы. При возвращении с другого компьютера импортировать новую копию с понятным названием и датой; старую можно архивировать после проверки.

## Ограничения и меры

Запрос постоянного браузерного хранения может быть отклонён; очистка данных пользователем всё равно удаляет локальную базу. Предусматриваем экспорт, дату последней созданной копии, обработку нехватки места и понятный статус сохранения. [Условия хранения браузером](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

Обновление приложения не перезагружает активный бой автоматически. Миграции хранилища версионируются; несовместимое обновление не должно уничтожать старые данные. Конкурирующие вкладки проверяют ревизию кампании в транзакции. Устаревшее изменение отклоняется; редактор предлагает скопировать текст и обновить страницу.

## Условия принятия платформы

1. После первоначальной загрузки приложение полностью закрывается и открывается в авиарежиме.
2. Без сети создаются две кампании, записи, сессия и бой; поиск также работает.
3. Переключение кампаний и перезапуск сохраняют отдельные события, здоровье, раунд и ход.
4. Экспорт и импорт файла восстанавливают ссылки и бой в новой независимой копии.
5. Повреждённый файл, неизвестная версия и нехватка места дают понятную ошибку без частичного импорта.
6. Проверка проводится на компьютере владельца; до неё не утверждаем совместимость с его конкретными ОС и браузерами.
