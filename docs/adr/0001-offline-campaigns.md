# ADR 0001: автономная работа и отдельные кампании

Дата: 2026-09-27.

Статус: требования подтверждены владельцем; PWA и техническая схема предложены для прототипа.

## Контекст

Компьютер и телефон одинаково важны. Требуется работа без интернета и сохранение нескольких кампаний. Автоматическую синхронизацию можно исключить. Приоритеты: сюжет, бой и история событий. [Исследование аналогов](../research/tools-comparison.md) поддерживает сочетание локальной базы знаний и специального экрана проведения.

## Решение для прототипа

- Адаптивная PWA без регистрации. Установка и обновления используют сеть; подготовленное приложение работает без сети.
- Локальная IndexedDB для данных; service worker и Cache API для файлов интерфейса. Все обязательные ресурсы поставляются вместе с приложением.
- Каждая кампания имеет стабильный ID, свою базу записей, сессии, журнал и бои. В интерфейсе всегда видно активную кампанию.
- Перенос между устройствами — экспорт и импорт файла. Автоматического слияния изменений нет.
- Первый модуль правил — `dnd-5.5e-2024`, с фиксируемой версией источника `srd-5.2.1`. Последующие обновления не меняют правила существующей кампании молча.
- Фреймворк интерфейса и библиотеку доступа к IndexedDB выбираем при создании прототипа; отдельный backend не требуется.

## Рассмотренные варианты

| Вариант | Соответствие задаче | Вывод |
| --- | --- | --- |
| PWA с локальными данными | Общий интерфейс на телефоне и компьютере, автономность после загрузки; нужны экспорт и проверка поведения браузеров | Первым проверяем прототипом |
| Устанавливаемое приложение с локальной базой | Подходит автономному сценарию; отдельная упаковка и проверка на каждой целевой ОС | Резервный путь при ограничениях PWA |
| Веб-приложение с сервером и синхронизацией | Добавляет аккаунты, сервер и разрешение конфликтов | Не входит в первую версию |

Основание для веб-варианта: [офлайн-работа PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation), [транзакции IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API). Выбор варианта — проектный вывод, не утверждение, что он уже проверен в этом приложении.

## Сохранение и резервная копия

Автосохранение пишет изменения локально; «Сохранено» показывается после успешной транзакции. Экспорт создаёт отдельный файл, который переживает удаление данных приложения. Локальная история внутри той же базы не заменяет внешнюю копию.

Для первой версии предлагаем `*.dmw.json`: `formatVersion`, `exportedAt`, метаданные кампании, версия правил, записи, связи, сессии, сцены, журнал, бои и участники. Экспорт — согласованный снимок одной кампании; текстовые материалы включены полностью, сетевые ссылки не считаются сохранённым содержимым. Вложения пока вне объёма.

Импорт сначала проверяет версию формата, типы полей, уникальность ID и все ссылки. Первая версия импортирует **как новую кампанию**, переназначая ID и внутренние ссылки. Существующие кампании не перезаписываются. Повторный импорт явно создаёт отдельную копию; автоматического объединения нет. Запись выполняется атомарно, ошибка оставляет прежнее хранилище целым.

Перенос: экспортировать на компьютере → передать файл любым доступным способом → импортировать на телефоне. Копии дальше независимы. При возвращении с телефона импортировать новую копию с понятным названием и датой; старую можно архивировать после проверки.

## Ограничения и меры

Запрос постоянного браузерного хранения может быть отклонён; очистка данных пользователем всё равно удаляет локальную базу. Предусматриваем экспорт, дату последней созданной копии, обработку нехватки места и понятный статус сохранения. [Условия хранения браузером](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

Обновление приложения не перезагружает активный бой автоматически. Миграции хранилища версионируются; несовместимое обновление не должно уничтожать старые данные. Открытие второй вкладки не должно приводить к незаметной перезаписи: для прототипа допустим один редактирующий экземпляр, остальные показывают предложение продолжить в нём.

## Условия принятия платформы

1. После первоначальной загрузки приложение полностью закрывается и открывается в авиарежиме.
2. Без сети создаются две кампании, записи, сессия и бой; поиск также работает.
3. Переключение кампаний и перезапуск сохраняют отдельные события, здоровье, раунд и ход.
4. На телефоне работают экспорт и импорт файла; на втором устройстве восстанавливаются ссылки и бой.
5. Повреждённый файл, неизвестная версия и нехватка места дают понятную ошибку без частичного импорта.
6. Проверка проводится на компьютере и телефоне владельца; до неё не утверждаем совместимость с его конкретными ОС и браузерами.
